## 三、语音链路（两条）

### 路径 A：云端语音（已工作）

```
小智硬件麦克风 → xiaozhi.me 云端(ASR+TTS) → MCP tools/call → LAAP 电脑控制
```

13 个工具注册到真实 broker：`voice_command` `pc_scroll` `pc_click` `pc_type` 等。

### 路径 B：音频流直连（已工作，完全脱离云端）

```
小智硬件(ESP32) ──WS──▶ LAAP XiaozhiAudioServer
                              │ Opus 解码(PyAV)
                              │ 能量 VAD + 看门狗
                              │ faster-whisper 本地 ASR
                              │ LAAP 大脑/电脑控制
                              │ edge-tts 本地 TTS
                              │ Opus 编码 → 发回设备
```

实测离线闭环：
```
合成"帮我打开记事本" → 发 Opus → 本地识别("幫我打開機械本") 
→ 大脑回显 → edge-tts 合成 → 4073 bytes Opus 回发 ✓
```

## 五、三端联动

### 双通道选择

```
同一 WiFi → 局域网 ws://192.168.x.x:8765（10ms）
跨网     → 云端 wss://api.laap.cn/ws（30-150ms）
策略     → 先试 LAN，3 秒超时降级 CLOUD
```

### 生产级 10 项（全实现）

1. 认证：JWT(云端) + 预共享密钥(局域网)
2. 断线重连：指数退避 1→60s ±30% 抖动
3. 消息顺序：递增 seq
4. **幂等**：idempotency_key + 5 分钟缓存
5. 背压：队列上限 1000
6. 多租户：user_id + session_id 双校验
7. 可观测：延迟 P50/P95/P99
8. 限流：300 消息/分钟/节点
9. 优雅降级：LAN→CLOUD，视觉→DOM→文本
10. 审计：全动作留痕

### 云端中继（已部署）

```
https://api.laap.cn/ws
Cloudflare Worker + Durable Objects
按 user_id 分片 → 用户间物理隔离
离线消息暂存（100 条 / 5 分钟）
端到端测试 6/6 通过
```

## 六、数据面设计（关键决策）

**不做全帧广播。** 三端内存差异巨大（硬件几百 KB vs 电脑几 GB）。

```
控制面（轻量，全端同步）
  说了什么 / 谁在说 / 意图 / 数据引用 ID
  → 几十字节到几 KB

数据面（重载，只传引用）
  截图 / 录音 / 视频 / 文件
  → 存本地，只传 payload_id
```

这样小智硬件不会因为收到一张 4K 截图而爆内存。
