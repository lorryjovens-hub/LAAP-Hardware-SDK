# LBP 阶段一 —— 硬件清单与接线方案

> 目标：用 **¥1300 左右** 做出 5 个模块，跑通
> **枚举 → 拓扑发现 → 身体图式推导 → 自动 IK**。
>
> 不做变形，不做 48V，不做机械对接。**只验证协议**。

---

## 0. 三个必须先定的设计决策

这三条都会改变采购清单，所以写在最前面。

### 决策 1：总线用 CAN 2.0B，不用 CAN FD

| 项 | 结论 |
|----|------|
| 事实 | **ESP32 系列的 TWAI 控制器原生只支持 CAN 2.0B（最高 1 Mbps），不支持 CAN FD** |
| 影响 | 若一定用 FD，需外挂 MCP2518FD（SPI 接），每模块 +¥25 且固件复杂一档 |
| 带宽核算 | 20 关节 @ 10Hz = **190 kbps**，CAN 2.0B 的 1 Mbps 下占 **19%**，完全够 |
| 决策 | **阶段一用 CAN 2.0B @ 1 Mbps**。LBP 帧格式不变，只是物理层降级 |

> 想一步到位用 FD：LilyGO `T-2CAN-FD` 开发板（ESP32-S3 + MCP2518FD 双路 CAN，
> 外置支持 FD、内置 2.0B），约 ¥180。主控可以直接买这块。

### 决策 2：母线用 12V，不用 48V

| 项 | 结论 |
|----|------|
| 事实 | 48V 是为功率密度（同功率电流 1/4、I²R 降 16×）。但阶段一总功率 < 100W |
| 风险 | 48V 需要 hot-swap 控制器 + 隔离 DC-DC，每模块 +¥60，且接线危险 |
| 决策 | **母线 12V**，各模块本地 buck 到 6V（舵机）/ 5V（逻辑）。协议 profile 不变 |

### 决策 3：舵机用 MG996R，不用 MG90S

这一条最容易踩坑，算一下就明白：

```
四足总重约 2.0 kg  → 每腿承重 0.5 kg
髋关节力臂约 9 cm  → 静态保持力矩 = 0.5 × 9 = 4.5 kg·cm
工程要 2× 余量     → 需要 ≥ 9 kg·cm

MG90S：2.0 kg·cm  → 堵转。买回来装上去就是趴着不动
MG996R：13 kg·cm @ 4.8V → 刚好够
```

**MG996R 的代价**：55 g/个、堵转电流 2.5 A。12 个并联极限 30 A（不现实），
实测行走峰值约 **10 A**。电源必须按这个选。

## 2. 连接器定义（每个端口统一 12 pin）

用 **GX16-12 航空插头**（¥12/对，比 XH 耐用，能防插错方向）。

| Pin | 信号 | 说明 |
|-----|------|------|
| 1 | GND | 电源地（大电流，必须双线） |
| 2 | GND | |
| 3 | +12V | 母线（正式版 48V） |
| 4 | +12V | |
| 5 | CAN_H | 差分，双绞 |
| 6 | CAN_L | |
| 7 | PRESENT# | 在位检测。模块侧短接 GND，主机侧 10kΩ 上拉 3.3V |
| 8 | ID0 | 端口位置编码，模块侧跳线到 GND 或悬空 |
| 9 | ID1 | |
| 10 | ID2 | |
| 11 | SYNC | 1 kHz 硬件同步脉冲，3.3V LVCMOS |
| 12 | 备用 | 预留给 48V 高压检测 / 温度 |

### 端口 ID 编码方式

模块上的 ID0/ID1/ID2 用 **3 个焊盘 + 短接跳线**：

```
pos_id = 1     pos_id = 3     pos_id = 5
ID0  ●─●       ID0  ●─●       ID0  ● ○
ID1  ○         ID1  ●─●       ID1  ○
ID2  ○         ID2  ○         ID2  ●─●
     0           1+2=3           1+4=5
```

躯干侧 3 根 GPIO 上拉输入，读电平得对端的 `pos_id`（0–7）。
**这就是「我在哪个方向上被插上」的全部电气实现**——3 根线。

> 为什么 ID 放在模块侧而不是躯干侧：
> 语义是「你插在我的第几号口」，所以编码应该跟着端口走，而不是跟着模块走。
> 同一块腿插到 1 号口和 3 号口，ID 不同 → 身体图式不同。这正是我们要的。

## 3. 电源树

```
       ┌──────────────┐
       │ 12V 10A 开关电源 │  ¥45
       └──────┬───────┘
              │ 干线（16AWG，星形接到每个 GX16）
    ┌─────────┼─────────┬─────────┬─────────┐
    ↓         ↓         ↓         ↓         ↓
 ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐
 │leg 0 │  │leg 1 │  │leg 2 │  │leg 3 │  │spine │
 ├──────┤  ├──────┤  ├──────┤  ├──────┤  ├──────┤
 │12→6V │  │12→6V │  │12→6V │  │12→6V │  │12→5V │
 │XL4015│  │XL4015│  │XL4015│  │XL4015│  │MP1584│
 │ 5A   │  │ 5A   │  │ 5A   │  │ 5A   │  │ 3A   │
 ├──────┤  │      │  │      │  │      │  ├──────┤
 │→3×舵机│  │      │  │      │  │      │  │→S3   │
 │6V 3A │  │      │  │      │  │      │  │5V    │
 └──────┘  └──────┘  └──────┘  └──────┘  └──────┘
```

**电流核算**：

| 负载 | 稳态 | 峰值 |
|------|------|------|
| 单腿 3× MG996R | 0.3 A @ 6V | 2.1 A（3×0.7 行走） |
| 4 腿 | 1.2 A | **8.4 A** |
| 逻辑（5 ESP32） | 0.6 A @ 5V | 1.0 A |
| **12V 母线折算** | ~1.1 A | **~5 A** |

→ 12V 10A 电源有 2× 余量 ✓

**每条腿必须有本地 buck（XL4015 5A）**，不能用一个 6V 大电源拉长线：

- 舵机堵转瞬间拉 2 A，长线压降会让**同一总线上的其它腿也抖**
- 这是真实机器人布线的第一条纪律：**功率就近变换**

**电容**：每个 XL4015 输出并 **1000 µF 电解 + 100 nF 陶瓷**。
没有这个，四个舵机同时启动会把 6V 拉塌，ESP32 复位。

| **TWAI 驱动封装** | 收发 LBP 帧，中断 + 环形缓冲 |
| **端口 ID 扫描** | 6 个端口的 GPIO 读取 + PRESENT# 中断 |

### 5.2 spine 跑什么

```c
// 伪代码
void app_main(void) {
    bsp_init();                  // 已有
    lbp_master_init(1);          // CAN 1Mbps

    // 1. 枚举
    lbp_enumerate();             // 广播 ENUM_REQ，收 ENUM_ACK + BMD

    // 2. 拓扑发现
    for (each module) lbp_query_topology(id);   // TOPO_REQ/ACK + 端口 ID

    // 3. 把拓扑发给 PC（PC 侧算身体图式和 IK）
    wifi_send_json(lbp_topology_to_json());

    // 4. 收 PC 回来的身体图式，广播给所有模块
    lbp_broadcast_schema(schema_from_pc);

    // 5. 主循环：1kHz SYNC + 转发 CMD
    while (1) {
        gpio_pulse(SYNC_PIN);           // 1kHz 硬件同步
        lbp_relay_pending_cmds();
        vTaskDelay(pdMS_TO_TICKS(1));
    }
}
```

### 5.3 PC 侧（已有代码直接用）

身体图式的**推导和 IK 放在 PC**，不在 MCU 上：
- MCU 算不动 IK（DLS 迭代 + 数值雅可比）
- 而且 `laaper/body` 已经实现并验证过了（51/51）

```python
# PC 侧，已可用
from laaper.body import Topology, derive_schema, make_module

topo = Topology()
# 从 spine 上报的 JSON 重建
for m in spine_report["modules"]:
    topo.add_module(make_module(m["type"]), label=m["label"])
for c in spine_report["connections"]:
    topo.connect(c["parent"], c["port"], c["child"])

schema = derive_schema(topo)     # ← 身体图式推导
print(schema.summary())
q = schema.legs[0].ik(target)    # ← IK
```

### 5.4 leg 跑什么

```c
// ESP32-C3 从站
void app_main(void) {
    lbp_slave_init(&cfg);        // 上报 BMD
    servo_init_3ch();            // LEDC PWM 50Hz，3 通道

    while (1) {
        if (lbp_recv_cmd(&cmd)) {
            // 等到 T_EXEC 那一刻再执行（其他关节也在等）
            lbp_wait_exec_time(cmd.t_exec_us);
            for (i in 3) servo_set(i, cmd.q[i]);
            lbp_report_telem(actual_q);   // 回遥测
        }
        // 反射：舵机电流超限 → 立即卸力 + REFLEX 上报
        if (read_current() > 2500) {
            servo_release_all();
            lbp_send_reflex(OVER_CURRENT);
        }
    }
}
```

## 6. 组装步骤（按顺序，每步可验证）

### Step 1：躯干（半天）

1. 洞洞板上焊 ESP32-S3 排母
2. TJA1050 模块焊上（VCC→5V，GND，TX→GPIO4，RX→GPIO5）
3. MP1584 调到 5.0V（**先空载调好再接负载**）
4. 6 个 GX16-12 插座焊到板边
5. 每个插座的 pin 5/6 并联到 CAN 总线，pin 3/4 并联到 12V，pin 1/2 并联到 GND
6. **总线两端各焊 120Ω**（spine 一端 + 最远那条腿一端）
7. 上电：万用表确认 5V 正常、CAN_H/CAN_L 无短路

**通过标准**：断电测 CAN_H–CAN_L 电阻约 60Ω（两个 120Ω 并联）。

### Step 2：单条腿（1 天）

1. ESP32-C3 焊到洞洞板，引 3 路 PWM（GPIO0/1/2）
2. TJA1050 焊上（TX→GPIO6，RX→GPIO7）
3. XL4015 调到 **6.0V**（空载调，接舵机前必做）
4. 输出并 1000µF 电解（**注意正负极**）
5. 3 个 MG996R 装上亚克力连杆
6. ID0–ID2 跳线焊成想要的 pos_id
7. PRESENT# 短接到 GND

**通过标准**：单独给 12V，三个舵机都能用 PWM 测试代码转动，ESP32 不掉电。

### Step 3：双腿联调（半天）

1. 两条腿通过它们自己的 GX16 插座互相连（或都连到 spine）
2. 跑 CAN 回环测试：spine 发 ENUM_REQ，收到 2 个 ENUM_ACK

**通过标准**：两个模块 serial 号不同，BMD 能完整传回来（分片重组正确）。

### Step 4：四腿 + 拓扑（半天）

1. 四条腿接到 spine 的 port 0–3
2. 每条腿的 ID 跳线设成对应端口号
3. spine 读 6 个端口的 PRESENT# + ID → 打印拓扑

**通过标准**：拓扑打印出 `p0↔leg0, p1↔leg1, p2↔leg2, p3↔leg3`，与实际接线一致。

## 8. 风险清单（按踩坑概率排序）

| 风险 | 概率 | 表现 | 对策 |
|------|------|------|------|
| **电源塌陷导致 ESP32 复位** | 🔴 高 | 舵机一动就重启 | 每条腿本地 buck + 1000µF + 逻辑电源与舵机电源分开走线 |
| **MG996R 扭矩不够** | 🟡 中 | 腿撑不住、抖动、堵转发热 | 连杆缩短到 70mm，或换 20kg·cm 舵机 |
| **CAN 总线没终端电阻** | 🟡 中 | 时通时不通、误码 | 两端各 120Ω，量总阻值应为 60Ω |
| **舵机共地干扰 CAN** | 🟡 中 | 舵机启动时 CAN 丢帧 | CAN 用双绞线，远离电源线；收发器 5V 单独滤波 |
| **端口 ID 跳线接错** | 🟡 中 | 拓扑与实际不符 | 组装后逐口测量 ID 电压 |
| **开环舵机精度差** | 🔴 高 | IK 目标到了，实际偏 3-5cm | 阶段一接受；阶段二加 AS5600 磁编码器闭环 |
| **多模块 ID 冲突** | 🟢 低 | 两个模块抢同一 CAN 地址 | 用 serial 号做唯一键，地址由主机动态分配 |

### 已知的最大精度短板

**开环舵机没有位置反馈**，所以：
- 测试 7 的「到位误差 < 2cm」是宽松标准
- 真要做精确 IK 验证，必须加 **AS5600 磁编码器**（¥10/关节，I2C）到每个关节
- 12 个关节 +¥120，但能让精度到 ±0.5°

建议：**阶段一先开环跑通链路**，阶段二再加编码器。不要一上来就做 12 路编码器，
机械安装（磁铁同心度）很费时间，会拖垮进度。

## 10. 台架仿真（等货期间做这个）

硬件到货要 1–2 周。这段时间先把软件侧跑通，并拿到**真实硬件应当匹配的参照值**：

```bash
python tools/lbp_sim.py          # 完整流程
python tools/lbp_sim.py -v       # 显示每个关节角
```

它模拟 CAN 2.0B 总线（帧经真实编解码 + CRC + 分片），跑完整链路：

```
[1] 上电枚举     → 4 个 ENUM_ACK，BMD 分片重组
[2] 拓扑发现     → 读出各模块挂载端口
[3] 身体图式     → quadruped 12DOF 裕度+39.0mm COM(-0.024,0,-0.238)
[4] 带宽核算     → 10Hz 占 11.3%，1kHz 超载 1133%
[5] 下发站姿     → 四腿同 t_exec，IK 误差 0.01mm
[6] 时序一致性   → 线上耗时 45.8ms，距执行余量 454ms
[7] 功率核算     → 峰值 38.5W → 12V/3.2A
[8] 拔腿判定     → 后腿拒绝、前腿允许
```

**到货后逐项比对**：与 [3] 和 [8] 一致说明协议与接线都对；
不一致则查接线 / BMD，而不是怀疑算法。
