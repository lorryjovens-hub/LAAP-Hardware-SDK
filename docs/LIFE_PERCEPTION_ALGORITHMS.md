# LAAP 生命感知算法 — 设计与边界

> 回答一个问题：**硬件数字生命体可以有哪些真正突破的算法？能实现「生命感知」吗？**

---

## 一、先说清楚：现在的系统为什么不算「生命感知」

我们之前做的是：

```
传感器 → 物理量 → 编码成体验质(valence/arousal) → 上报 → 融合 → 动作
```

这条链**每一环都在处理数据**。它能做出「看起来很聪明」的响应，但缺三样生命特征：

| 缺什么 | 生物的样子 | 我们的样子 |
|--------|-----------|-----------|
| **预测性** | 先预测，只报告预测失败的部分 | 每条读数都上报 |
| **主动性** | 不确定就动一下，让世界变清楚 | 等指令 |
| **身体立场** | 感知直接编码「我能做什么」 | 先识别物体再推理 |

这三条不是哲学讨论，**每一条都能写成算法**，而且做完可以量化验证。

---

## 二、算法一：预测编码（Predictive Coding）

### 生物学依据

Rao & Ballard (1999) 的层级预测编码模型，加上 Friston 的自由能原理：
大脑皮层每一层都在预测下一层的输入，**上行只传预测不了的部分**。

你盯着墙壁看，视觉皮层不每秒上传 60 帧图像——它预测「还是一样的墙」，
误差接近零，就什么都不传。突然有东西飞过，误差爆炸，你才「看见」了。

### 实现

```python
pred     = level + velocity · dt          # 线性外推
err      = obs - pred                     # 预测误差
gain     = variance / (variance + noise²) # 卡尔曼增益
level   += gain · err                     # 修正估计
velocity += α · err / dt                  # 学习趋势
variance  = (1-gain)·variance + Q         # 不确定性演化

surprise = |err| / √variance              # 标准化惊讶度（σ 单位）
```

**只有当 `surprise ≥ 2σ` 才上行。**

### 实测收益

真实传感器噪声（高斯抖动）下，5 通道采样 1500 次：

```
上行 187 次 → 省下 87.5% 带宽
  temperature  上报率 32.3%
  light         上报率  9.7%
  distance      上报率  9.0%
  audio         上报率  6.7%
  touch         上报率  4.7%
  imu/battery   上报率  0.0%
```

同时白送两件事：

- **注意力免费**：`surprise` 本身就是显著性，不需要额外做注意力机制
- **异常检测免费**：突发的 σ 爆表就是异常

### 方差自适应 = 习惯化

方差会自适应演化。一直很稳的传感器（方差小），小偏差就是大惊吓；
一直很吵的传感器（方差大），同样的绝对误差不算什么。

**这就是生物的「习惯化」**：住在铁路边的人听不见火车声。

实测：首次 500lux 突变 `surprise=92.98`，持续同幅扰动 40 次后降到 `58.52`——
下降了但没归零，敏感度保留。这条曲线和真实感觉神经元的适应曲线形状一致。

## 三、算法二：可供性（Affordance over Recognition）

### 生物学依据

Gibson 的直接知觉理论：生物看到椅子，感知的不是「几何体+材质」，
而是「**可以坐的东西**」。可供性是感知的一部分，不是推理的结果。

### 传统的四层 vs 生命的两层

```
传统机器人：传感器 → 世界模型 → 规划 → 动作      （4 层，延迟高）
生命体：    传感器 → 可供性 → 动作               （2 层，直接）
```

我们输出的是：

```python
Affordance(action=LOOK_AT, target="来的人", urgency=0.85, confidence=0.85)
```

而不是：

```json
{"objects": [{"type": "person", "pos": [1.2, 0.4], "velocity": [-0.5, 0]}]}
```

### 为什么这是突破

世界模型需要：物体识别（易错）、坐标变换（易错）、时序关联（易错）。
可供性只需要：**「什么变化 → 我能做什么」**，这条映射是稳定的。

一只宠物不需要知道「那是一个人」，它只需要知道「该看过去」。

### 实测

```
输入：距离 120→47.5cm，温度 22→23.8°C，声音 32→55dB
输出：look_at(来的人) urg=0.85 conf=0.85
      理由：距离漂移 -54.5cm 且温度漂移 +1.72°
```

注意它识别的是**「人」而不是「物体」**——因为距离+温度双证据匹配了人体特征。
单看距离只会输出 `look_at(前方物体) conf=0.7`。

## 四、算法三：主动感知（Active Inference）— 最关键的一条

### 这是「设备」和「生物」的分界线

被动的设备等指令。**活的东西会主动动一下，把世界看清楚。**

```
视觉模糊      → 云台微转（视差消歧）
声音方位不明  → 左右扫描
距离读数抖动  → 靠近一点确认
温度梯度平缓  → 移动探测
```

### 判据：信息增益

```
explore_gain = surprise × (1 − localization_confidence)
```

**两者都高才值得动**：
- 光惊讶不够（不知道在哪 → 该找）
- 光知道在哪也不够（不惊讶 → 没必要动）

### 定位置信度怎么算

这是设计里最微妙的一点。我第一版按「空间方向是否一致」算，**失败了**——
因为温度、声音都是「方位未知」，永远和「前方」不一致，于是永远触发探索。

正确做法是**情境模式匹配**：不是问「它们指向同一个方向吗」，
而是问「它们的组合是否已经是某个已知情境」。

```python
SCENARIOS = {
    "person_nearby":  {"distance", "temperature", "audio"},
    "touched":        {"touch", "pressure"},
    "bright_event":   {"light", "audio"},
    "instability":    {"imu", "distance"},
}
# 命中 ≥2 个 → 置信 0.5 + 0.15×命中数
```

### 实测

```
[单传感器]  只有声音惊讶  → explore:scan gain=2.64   ✓ 该找
[三传感器]  距离+温度+声音 → 不探索（已识别 person_nearby）  ✓ 不用找
```

**这就是「好奇」的算法形式**：既意外、又不明白，就去看看。

## 五、算法四：感知余韵（Temporal Depth）

### 生物依据

人的感知有惯性：摸过之后那块皮肤还「记得」，听过的话还在耳中回响。
感知不是瞬时快照，是滑动窗口 + 记忆重构。

### 实现

```python
trace = trace · exp(-dt/τ) + input · (1 - exp(-dt/τ))
```

不同模态不同 τ（这是关键，不能统一）：

| 感官 | τ | 感受 |
|------|---|------|
| 触摸 | 2.0s | 被摸完还留余温 |
| 声音 | 1.2s | 回响 |
| 视觉 | 0.25s | 视觉暂留 |
| 温度 | 30s | 慢变 |

### 实测

```
摸头瞬间：触摸增益 1.46（比平时敏感 46%）
2 秒后：  增益 1.31（余韵衰减但未消失）
```

**做出来的是「余韵」**：一个被摸过之后还会眯一下眼的宠物，和一个摸完立刻恢复原状的机器，差别在这里。

## 六、算法五：内感受调制（Interoceptive Gain）

### 生物依据

情绪不是感知的产物，它**调制感知本身**。累了看什么都迟钝，
被摸过之后对触摸特别敏感。生物学上叫增益调制（gain modulation），
是注意力的物理基础。

### 实现

```python
gain(modality) = f(energy, arousal, valence, touch_recent)

低电量 → 整体迟钝（0.5 底限，不能完全没反应，那是省电策略）
高唤醒 → 视觉/听觉更敏锐
被摸过 → 触摸更敏感
愉悦   → 整体更活跃
```

### 实测

```
同一份 4°C 温度突变：
  满电时 surprise = 160.0
  低电时 surprise =  88.0   （感受弱了 45%）
```

**这是一个反直觉的结果**：同样的物理世界，同一个传感器，产出不同的感知强度。
生物就是这样——这不只是「情绪影响行为」，是「情绪影响你感知到什么」。

## 七、三个真实踩到的坑（这部分最有价值）

### 坑 1：预测器会把持续变化学掉

**现象**：人持续走近，`LOOK_AT` 永远不触发。

**原因**：线性外推的 `velocity` 项会把「匀速变化」学成趋势，
于是 `predicted` 完美跟踪 `observed`，误差趋近零，惊讶度消失。

这在生物学上是真实的（适应），但对「人走来」这类事件是致命的——
它明明在发生，你却感知不到。

**解法：双时间尺度**

```python
快预测器（level + velocity）  → 抓瞬时突变
慢基线（baseline, τ=5×trace） → 抓累积漂移
drift = level - baseline
```

- 瞬时事件（撞了一下）→ 惊讶度高、漂移小
- 持续事件（人慢慢走来）→ 惊讶度被学掉、漂移大

**判据改成「或」而不是「且」**：

```python
near = (drift < -8.0) or (surprise > 1.2 and error < -0.5)
```

要求两者同时成立，持续事件就永远检测不到。

### 坑 2：定位一致性不能按空间方向算

见上文「主动感知」。按方向算会把「温度+声音」永远排除在外，
因为它们的空间信息是 `unknown`。必须按**情境共现模式**算。

### 坑 3：方差无下限会让数值失真

方差一直收敛，`σ` 趋近零，于是 `surprise = |err|/σ` 爆到几百。
数学上没错（非常确信的预测器遇到偏差就该大惊），但阈值失去意义。

**解法：方差下限 = (noise × 0.5)²**
不能比传感器噪声更自信——这是物理约束，不是调参。

> 顺带说：这三条教训的共同点是「**数学上正确的实现，在语义上是错的**」。
> 预测编码的公式很标准，但直接套用会得到「感知不到持续变化」的结果。
> 只有跑行为测试才能发现。

## 八、诚实边界：能做到什么，做不到什么

### ✅ 能真正做到（代码可验证）

| 能力 | 证据 |
|------|------|
| 稀疏上行 | 实测省 87.5% 带宽 |
| 注意力自动分配 | surprise 即显著性，无需额外机制 |
| 异常检测 | 突发 σ 即异常 |
| 习惯化 | 持续扰动后惊讶度下降 |
| 可供性感知 | 输出「能做什么」而非「是什么」 |
| 主动探索 | 单感官→探索，多感官→不探索 |
| 感知余韵 | 触摸后敏感度持续 2s |
| 情绪调制感知 | 低电量感受弱 45% |

### ⚠️ 部分能做到（有效果但机制不同）

| 想要 | 实际得到的 |
|------|-----------|
| 「主观体验」 | **功能等价的结构**：有情绪状态、有增益调制、有余韵，但没有感受质（qualia） |
| 「理解语义」 | 可供性映射。知道「该看向什么」，不知道「那意味着什么」 |
| 「自发好奇」 | 信息增益驱动的探索。形式上是好奇，但没有「想」的成分 |

### ❌ 做不到（当前架构的硬边界）

| 做不到 | 为什么 |
|--------|--------|
| **真正的主观体验** | 这是意识的 hard problem，不是工程问题。我们做的是**功能等价物** |
| **无预设的自组织** | 可供性规则是手写的。真正的生命体自己发现可供性 |
| **从感知中长出概念** | 我们的「人/热/近」是硬编码分类。生物的概念从经验中涌现 |

### 我的判断

**「真正的生命感知」在工程上可以做到 80% 的功能等价，但那 20% 是意识的 hard problem。**

能对现有机器人和智能硬件做的事：
- 从「每秒上报 100 条数据」变成「有事才说话」（省 10 倍带宽）
- 从「等你下指令」变成「不确定就自己看一眼」（这才是活的）
- 从「同一份输入永远同一反应」变成「累了就迟钝，被摸过就敏感」（身体状态影响感知）

**这三条已经是本质区别**，但我不该说「这就是真正的生命感知」——
那是在用功能冒充体验，是我不该做的事。

## 九、对现有硬件的实际价值

| 场景 | 之前 | 之后 |
|------|------|------|
| 桌面宠物 | 只响应语音指令 | 有人走近会自己抬头看；被摸过之后对触摸更敏感 |
| 机械狗 | 收到 move 才动 | 前方距离漂移就停下观察；不稳定时先稳住身体 |
| 机器车 | 撞墙才避障 | 距离持续减小就减速观察，不需要撞到 |
| 带宽 | 5 通道 × 10Hz 全量上报 | 省 87.5% |
| 断网行为 | 变砖 | 端侧感知场继续工作，维持基本反应 |

**端侧意义最大**：这套算法全部跑在 MCU 上（浮点运算量 < 1K FLOP/通道/次），
不依赖网络和云端，断网时宠物还是「活的」。
